# Navigation and Routing

Use this skill when introducing new screens, defining routing flow paths, configuring authorization route guards, or managing overlays (dialogs, bottom sheets).

## When to use this skill
- When creating a new screen widget and mapping a route to it.
- When passing parameters through URL paths or query configurations.
- When configuring transition animations or binding cubit dependencies locally to a route.

## Guidelines
1. **Always use Typed Routes**: Define routes as typed `GoRouteData` classes instead of raw string paths.
2. **Context-Safe Navigation**: Always use extensions (`safePush`, `safeGo`, `safePop`) from `core/extension/context_extensions.dart` to prevent navigation calls on unmounted widgets.
3. **Route BLoC Scoping**: Register and inject Cubits required for the page using `RouteBuilderHelper.buildPage(..., providers: ...)` to automatically limit the Cubit lifecycle to the screen's route.

## Instructions

### Step 1: Add Path String in `RoutesStrings`
Declare your route path constant in `lib/core/navigation/routes/core/routes_strings.dart`:
```dart
abstract class RoutesStrings {
  static const String myNewScreen = '/my-new-screen';
}
```

### Step 2: Define Route Class
Open `lib/core/navigation/routes/app_routes.dart` (or its respective sub-part, e.g. `routes/main/main_shell_routes.dart`):

1. Annotate the class with `@TypedGoRoute` and define hierarchy if child routes are needed.
2. Extend `GoRouteData` and implement `buildPage`:

```dart
@TypedGoRoute<MyNewScreenRoute>(
  path: RoutesStrings.myNewScreen,
)
@immutable
class MyNewScreenRoute extends GoRouteData {
  const MyNewScreenRoute();

  @override
  Page<void> buildPage(BuildContext context, GoRouterState state) =>
      RouteBuilderHelper.buildPage(
        state: state,
        child: const MyNewScreen(),
        transition: AppTransitionType.slideUp, // Choose transition
        providers: [
          // Local bloc providers mapped to this route
          BlocProvider<MyNewCubit>(create: (_) => di()),
        ],
      );
}
```

*Note: After writing the route, execute `flutter pub run build_runner build --delete-conflicting-outputs` to generate the `$MyNewScreenRoute` extension mixin.*

## Executing Navigation

Use the types generated by `go_router_builder`:

```dart
import 'package:Onyx_driver/core/extension/context_extensions.dart';
import 'package:Onyx_driver/core/navigation/routes/app_routes.dart';

// 1. Navigation with go (replaces stack)
context.safeGo(const MyNewScreenRoute());

// 2. Navigation with push (pushes on top)
context.safePush(const MyNewScreenRoute());

// 3. Navigation with parameters
context.safePush(OtpRoute(phone: '0123456789'));

// 4. Safe Pop
context.safePop();
```

## Showing Dialogs & Overlays
Avoid calling standard `showDialog` or `showModalBottomSheet` directly. Use the core `OverlayManager` service registered in DI:

```dart
import 'package:Onyx_driver/core/navigation/overlay/overlay_manager.dart';

getIt<OverlayManager>().showCustomBottomSheet(
  context: context,
  child: const MyCustomSheetWidget(),
);
```
